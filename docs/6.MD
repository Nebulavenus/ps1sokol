# Track-Following & Collision Systems

## Overview
This document covers the implementation of car-to-track adherence and the collision response system for horizontal barriers.

## 1. Track-Following (Ground Snap)
To keep the car on the track without full physics, we use vertical raycasting.

### Logic:
- **Vertical Raycast**: A ray is fired down from the car's center.
- **Surface Hit**: Returns `hitPos` and `hitNormal`.
- **Clamping**: `player.position.y = hitPos.y + suspensionOffset`.
- **Orientation**: The car's Up axis is aligned with the `hitNormal`.

## 2. Robust Orientation Math
A "Gimbal Lock" issue was fixed where the car would spin wildly on vertical slopes.

### The Fix:
Instead of re-calculating everything from a global Forward vector, we derive the new basis from the **previous frame's Right vector**:
```nim
let prevRight = state.player.rotation * vec3(1, 0, 0)
let newForward = norm(cross(surfaceNormal, prevRight))
let newRight = cross(newForward, surfaceNormal)
state.player.rotation = fromCols(newRight, surfaceNormal, -newForward, state.player.position)
```

## 3. Horizontal Barrier Collisions
Barriers prevent the car from leaving the road and allow for "wall sliding."

### Collision Detection:
- **Short Horizontal Rays**: Fired in 4-8 directions around the car.
- **Push-Out Response**: If a ray hits a wall, the car is moved back by:
  `pushVector = wallNormal * (rayLength - hitDistance)`.

### Normal Correction (Inside-Out Fix):
To handle meshes with inconsistent winding, we ensure the normal always faces the car using the dot product:
```nim
var wallNormal = norm(cross(v1 - v0, v2 - v0))
if dot(rayDir, wallNormal) > 0:
  wallNormal = -wallNormal # Flip if pointing away from collision
```

## 4. Asset Integration (embedfs)
The engine was refactored to use `embedfs` for asset abstraction.
- **Small Assets**: Embedded as C-string literals (`embed = true`).
- **Large Assets**: Read from disk via the same API (`embed = false`) to bypass MSVC's 64KB string literal limit.
- **Cache Redirection**: Baked AO files are saved relative to the `embedfs` root directory.
