# Advanced PLY Loading & Retro Rendering Troubleshooting

## Overview
This document details the development of a feature-complete PLY loader and the resolution of common "invisible" rendering and dithering bugs in a Nim/Sokol retro-engine.

## 1. Feature-Complete PLY Loader
The loader was upgraded to support vertex colors and robust property mapping.

### Key Features:
- **Vertex Color Packing**: Supports `uchar red green blue alpha` properties.
- **Triangulation**: Converts quads to triangles on-the-fly.
- **Dynamic Property Mapping**: Uses a `Table` to find columns for `x, y, z, nx, ny, nz, s, t, r, g, b, a` regardless of their order in the PLY header.

### Color Packing Logic:
```nim
proc packColor(r, g, b, a: uint8): uint32 {.inline.} =
  ## Packs four 8-bit color channels into a single 32-bit integer.
  ## Expected by Sokol's UBYTE4N format.
  result = (uint32(a) shl 24) or (uint32(b) shl 16) or (uint32(g) shl 8) or uint32(r)
```

## 2. Troubleshooting Checklist

### Why is my model invisible?
1. **Back-face Culling**: Blender might export CW winding. Fix by swapping indices in the loader or setting `cullMode: .NONE`.
2. **Applied transforms**: Always use `Ctrl+A > All Transforms` in Blender before exporting.
3. **Scale**: The model might be too large or too small. Check the `u_mvp` matrix and camera clipping planes.

### Why is dithering invisible?
- **MSAA Conflict**: MSAA averages pixels, which destroys the dither pattern. **Disable MSAA** (`sampleCount: 1`) for retro effects.
- **Resolution**: High resolutions (1080p+) make 4x4 dither patterns nearly invisible. Render to a lower-resolution offscreen pass for a true retro feel.

## 3. Critical Bug: Degenerate Triangles
A copy-paste error in the face parsing loop caused all triangle indices to point to the same vertex:
- **Error**: `parts[1], parts[1], parts[1]`
- **Fix**: `parts[1], parts[2], parts[3]`
This resulted in zero-area triangles that the GPU skipped during rasterization.
