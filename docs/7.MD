# Music Integration & Audio Architecture Evolution

## Overview
This document chronicles the implementation of a QOA music system and the architectural shifts required to achieve stutter-free, high-performance audio in a Nim/Sokol game.

## 1. QOA Music & Mixing
Music was integrated using the **Quite OK Audio (QOA)** format for its high compression and fast decoding.

### The Mixer Logic:
```nim
# Mixing Engine and Music
let engineSample = generateEngineSample() * engineVolume
let musicSample = currentMusicBuffer[musicPos] * musicVolume
finalSample = clamp(engineSample + musicSample, -1.0, 1.0)
```

## 2. Performance Debugging (The "Freeze" Saga)
Several subtle bugs were identified that caused the game to stutter or lock up:
1. **Per-Sample Indirection**: Accessing `playlist[i].pcmData[j]` inside the audio loop was too slow. 
   - *Fix*: Hoist the PCM pointer *outside* the loop.
2. **Closure Capture**: `loadPlaylist` captured loop variables by reference, causing all tracks to point to the same data.
   - *Fix*: Refactored to a stateless decoder helper.
3. **Audio Callback Complexity**: Performing any logic (like searching for the next song) inside the 2048-sample callback blocked the main thread.

## 3. The Final Architecture: Producer/Consumer
The breakthrough was moving all "heavy" work out of the audio callback entirely.

### The Roles:
- **The Producer (`main.nim`)**: Runs during the game's `frame()` loop. It checks if the `MusicCircularBuffer` is low and decodes a few thousand QOA samples to refill it.
- **The Consumer (`audio.nim`)**: The Sokol-Audio callback. It only performs a raw memory copy from the circular buffer to the sound hardware.

### Benefits:
- **Constant Performance**: CPU usage is identical regardless of song length.
- **Zero Latency**: No more "game advance" stutters because the audio thread never blocks for decoding.

## 4. Advanced Engine Tuning
The engine sound was upgraded from a "buzz" to a "growl" by manipulating harmonics:
- **Fundamental (1.0x)**: The core pitch.
- **Octave (2.0x)**: Provides clarity at high RPMs.
- **Sub-Harmonic (0.5x)**: Provides a deep, mechanical rumble at idle.
- **Buffer Stability**: `SAUDIO_NUM_SAMPLES` was increased to `2048` to ensure a stable stream on all hardware.
